## Correctness

The gadget in [`proof.md`](../../work/proof.md) lines 7–14 matches the five sets and budget in [`algorithm.py`](../../work/algorithm.py) lines 19–29. It gives a legal explicit target for every source graph in the executable contract, including no-edge graphs and binary-scale `n` with few active vertices. The forward witness in proof line 18 represents each of the five edge rows with four local sets whenever an endpoint belongs to a cover. Thus a source YES instance yields a target witness; by contrapositive, a valid target `NO-SOLUTION` implies source `NO-SOLUTION`. Both problems have a valid output on every admitted instance.

For an arbitrary target basis, deleting duplicate, empty and unusable sets preserves every represented family member. Each vertex row requires either its pair or both singleton sets. If the pair coexists with a singleton, replacing the pair by the opposite singleton preserves the only row that can use the pair; this justifies the normalization in proof line 22 and the code at `algorithm.py` lines 43–59. Four distinct local sets are forced by the private occurrences `(c1,a)`, `(c2,b)`, `(c3,d)`, `(c4,e)`; no subset of two corresponding rows contains both designated elements. An edge with neither endpoint split needs four distinct local sets carrying its four different vertex symbols and another set for the private-only fifth row. Private symbols prevent sharing between edge gadgets. Hence `|B| >= q + |T| + 4m + u`, so the code's choice of one endpoint for each edge outside `T` yields a cover of size at most `|T|+u <= k`. This also covers target witnesses with slack, extra useful sets, and alternate representations. I found no missing mathematical premise in proof lines 20–28.

Construction uses at most `q<=2m` active vertices, `2q+4m<=8m` universe elements, `q+5m<=7m` rows, and `2q+16m<=20m` incidences. The output labels take `O(log(m+1))` bits and `K=q+4m+k` takes `O(log(k+m+1))` bits. Sorting active vertices and building rows is polynomial in the explicit input length. Recovery reconstructs these rows and compares each supplied basis set with rows, polynomial in input plus target-output length; its cover has at most `2m` labels of `O(log(n+1))` bits. These are bounds on F and G, not on solving Set Basis.

The existing injected loop in [`check.py`](../../work/check.py) lines 124–153 invokes both command modes, gets a target answer from the SCIP feasibility oracle, validates direct unions, and checks recovered source membership; [`verify.py`](../../work/verify.py) lines 48–105 uses a separate Z3 encoding. I inspected the closure argument used by the first oracle: enlarging a useful subset to the intersection of all rows containing it cannot remove it from any row it served, so the feasibility model is exact. The recorded 112 and seven source cases are finite evidence only. I did not rerun those suites. [`check_redundant_witness.py`](check_redundant_witness.py) independently constructed a valid witness containing a pair with a singleton, duplicate, empty and unusable sets, and checked subprocess recovery; it passed under `uv run --locked`.

**Executable defect.** The fixed question admits arbitrary nonnegative binary parameters; [`work/contract.md`](../../work/contract.md) places no digit limit on the JSON integer representation. `algorithm.py` lines 71–73 rely on Python's default JSON-to-integer and integer-to-JSON conversions. Python 3.12 imposes a 4300-decimal-digit conversion limit. [`check_large_parameter.py`](check_large_parameter.py) sends a legal edgeless instance with a 4301-digit `k`; `uv run --locked` reproduced exit status 1 and `Exceeds the limit (4300 digits) for integer string conversion`. This is an input of only a few thousand bytes. The same boundary also affects printing a large `K`. Thus the claim in proof line 32 that the executable forward map handles binary-scale `k` lacks the premise that parsing and printing are unbounded. Fix the command boundary so it accepts and emits arbitrarily long integer encodings, then test F and G end to end on such an instance; retain the current gadget proof and other verification.

## Novelty and literature

Search date: 2026-09-26. The closest accessible primary source is [Björklund and Martens, *The Tractability Frontier for NFA Minimization*](https://people.cs.umu.se/henrikb/papers/icalp08.pdf), Lemma 4, pp. 6–8: it prints the same five rows, budget `n+4|E|+k`, forward basis and an endpoint-adding recovery in its normal-basis converse. Lemma 5, pp. 8–10, proves equivalence with ordinary Set Basis on its restricted input class and explicitly normalizes a pair coexisting with a singleton. The paper attributes Lemma 4 to [Jiang and Ravikumar, *Minimal NFA Problems Are Hard*](https://epubs.siam.org/doi/10.1137/0222067) (1993); its full text was not available in this search. The earlier [Stockmeyer report, *The Set Basis Problem Is NP-Complete*](https://books.google.com/books/about/The_Set_Basis_Problem_is_Np_complete.html?id=NtDmtgAACAAJ) (1975) was located bibliographically, but its primary proof was not available for comparison. Coverage of those two original proofs remains unresolved.

The current theorem is a reconstruction and consequence of the published gadget and ordinary-basis equivalence, not a new hardness result. The deterministic direct counting argument for arbitrary ordinary witnesses is shorter than the published normalization route, but the core counting and endpoint-adding steps already appear in Lemma 4. The executable F/G artifact and its explicit all-output contract are the identifiable contribution here. [`proof.md`](../../work/proof.md) line 3 correctly disclaims novelty for the gadget; any later manuscript should avoid presenting the decoder itself as a new theorem without a stronger literature comparison.
